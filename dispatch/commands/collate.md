# /collate —— 群集结果复核流水线

前置：本会话刚回收了并发子代理的若干份汇报（带 P0/P1/P2 分级与来源轨道）。你是主会话模型，按本流程把「采信」变成「验证过的采信」。抽查比例参数：`$ARGUMENTS`（空则 30）。

## 第一步：建台账

从各份汇报提取全部问题条目，列表：

| 序号 | 轨道（flashx / heavy / …） | 严重度 | 标题 | 位置（文件:行号） | 声称证据 |

## 第二步：分级定复核方式（按此优先级）

1. **双轨互证**：两个独立轨道报告了同一问题（位置与实质相同）→ **自动「已确认（双轨）」，无需读行**。
2. **P0 / P1（任何轨道）**：**全量复核**。亲自 Read 引用行比对原文——行号错则纠正，证据站不住则降级或剔除；复核通过才准进最终报告。
3. **轨道间矛盾**（同一问题两轨结论相反）：**强制复核**，亲自读行定谳，写明定谳依据。
4. **flashx 轨 P2**：按比例抽查（默认 30%、至少 3 条，优先将进入核心结论的条目）；未抽到的标「flashx 单轨未复核」，采信时须在产出中注明。
5. **heavy/5.3 轨 P2**：默认采信，标「单轨证据」；可顺手抽查。

## 第三步：执行复核（动作规范）

- **亲自 Read 引用行**——不凭记忆、不凭报告转述；
- 每条记终判：`证实 / 行号已纠 / 降级 / 剔除 / 升级`；
- 三态标注保留：`已确认 / 怀疑未验证 / 无法确认`（写明缺什么证据）。

## 第四步：产出

1. **终判表**：全量条目 → 复核方式（双轨/全查/抽查/矛盾定谳/未抽查）→ 终判；
2. **抽查统计**：应查 X / 实查 Y / 抽中问题率（抽中即发现站不住的比例，偏高说明该轨需要 heavier 档）；
3. **账本**：向工作区根 `.zcode/subroute-collations.json` 追加一条（数组 append，文件不存在则创建）：

```json
{
  "date": "<ISO 时间>",
  "task": "<一句话任务描述>",
  "tracks": [{ "tier": "flashx", "findings": 7 }, { "tier": "heavy", "findings": 5 }],
  "verified": { "full": 3, "sampled": 4, "dualTrack": 1 },
  "outcome": { "confirmed": 6, "downgraded": 1, "rejected": 0 },
  "notes": "<矛盾定谳与无法确认项摘要>"
}
```

## 铁律

- 复核是**主会话职责**，不派发子代理——复核的对象就是子代理的结论；
- flashx 未抽查的 P2 **不得标「已确认」**，最多「单轨未复核采信」；
- 账本只记事实与终判，不复制报告正文（主上下文省着用）；
- 若群集报告尚未回收就收到本命令：如实说明「无待复核报告」，不凭空造台账。
