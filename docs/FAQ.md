# FAQ —— 已知限制与常见问题

> 从根 README 迁入。速览请回 [README](../README.md)；设计背景见 [DESIGN.md](DESIGN.md)。

## 已知限制

- **生效时序（1.0.0 修正表述）。** agent 定义（`agents/*.md`）由注册表在**回合边界**重扫：写入后同回合派发必失败、同回合等待也无效（三次实测 + 探针 8 秒对照定谳），下一条消息生效、不必新开会话；**技能与命令仍是会话启动快照**，改动需新开会话。
- **触发依赖 AGENTS.md 条款。** doctor 检查项 6 校验的是本机 AGENTS.md；其他用户无此条款时技能仍可按描述触发，但逐次确认纪律的强制性减弱。
- **三档通道统一走 magpie 中转。**（2026-11-19 起：bigmodel 直连 1113 额度、tokenrhythm 461 通道先后失效，且 coding plan 未开放 FlashX）`magpie` 不在列或被禁用时各档不可用，doctor 检查项 4 报警；直连恢复后可切回（见 CHANGELOG 1.3.4）。
- **并发无硬上限。** 只有纪律建议值；硬闸仅工作流 `max_concurrency`。
- **子代理工具面常缺 ListModels。** 偶发验证「可用则自证，不强求」，不可用时以宿主环境标识为准并如实标注。

> 已修复：doctor 检查项 1/5 的源码路径曾在早期版本写死本机路径，1.0.0 已恢复 `~/.zcode/workspace/<工作区名>/plugins/dispatch` 通用写法。

## 常见问题

**每次派发前都要确认，不烦吗？**
并发消耗真实额度，逐次确认是刻意的（D1）。嫌烦就**把模型和并发数一起点名**：「用 flashx 4 路做 X」——两者都点名才构成豁免；只点名模型不算，仍会被问并发数。

**flashx 的结论能直接用吗？**
关键结论（数字/事实/路径）不能直接采信，验收时抽 1-2 条改派高档模型复核，不一致以复核为准（D3）；群集报告回收后可跑 `/dispatch:collate` 做系统分级复核。

**改了插件文件 / AGENTS.md，为什么没生效？**
agent 定义改完下一条消息生效（回合边界重扫）；技能与命令改完要**新开会话**。两者时序不同，别混。

**派发报 `reasoning-level-missing`？**
中转站代理的 agent 定义缺 `thoughtLevel:` 字段（D6），与 `model:` 并列补上即可。

**`/route` 和旧 subroute 插件什么关系？**
1.0.0 已把 subroute 的偏好层（/route）与复核层（/collate）并入本插件，状态文件路径完全一致、数据无缝沿用。装了本插件就**停用/卸载 subroute**，避免双注册。

**怎么卸载？**
ZCode 设置 → 插件管理 → 卸载，再删除本地市场条目。插件以声明式为主＋一个确认闸钩子；运行时只写 `~/.zcode/dispatch/` 两个状态文件（confirm.json 确认窗标记、gate.json 应急开关），卸载后连同该目录一并删除即可；偏好 JSON 由用户命令显式写入，属数据不算残留，无隐藏进程。

**敲 /dispatch:flash 这类命令派发会被闸拦吗？**
会。命令调用即点名（跳过评分确认），但派发 prompt 前 160 字符要标 `[named]` 才过硬闸；1.3.0 起命令已内置该指引。

**动态工作流为什么不设闸？**
明示豁免（D9）：工作流自带「脚本编写 → 类型检查 → 用户确认」确认链；且 hook 层无法校验工作流脚本内容，拦则误伤正规流程。

**subroute 旧插件要处理吗？**
dispatch 1.0.0 起要求卸载 subroute@subroute-local，否则 /route、/collate 双注册且语义分叉。检查方式：`/dispatch:doctor` 第 7 项。
